# 在 App 中用 GitHub 合作写论文

## 当前能做什么

0.3.6 已在 Windows 真实 GitHub App 会话下验证：私有项目创建与关联、首次上传、下载到第二个独立目录、两副本交替修改同步、取消后再次同步。普通使用者无需终端或 Git 命令。尚未完成第二个人的邀请接受、真实 Mac GUI 和受信签名验收，不把同账号两副本测试冒充两账号协作验收。

发布者只需配置一次，见[GitHub App 配置步骤](<GITHUB-APP-SETUP.md>)；以后普通使用者不注册 App、不提供 PAT、不安装 Git、不输入命令。密码始终只在 GitHub 官方网页输入。当前版本使用内置的公共 App 标识；显式禁用发布者配置的构建仍不可登录。

## 先管理本机项目

项目首页列出全部已登记论文，可搜索并从“打开本地论文”／“新建论文”添加文件夹，入口跨重启保留。点击项目进入单篇编辑页：左侧是当前文件树与章节大纲，中间源码，右侧 PDF；点击目录箭头展开／收起，点击大纲定位当前源码行。首页“最后修改”读取真实源文件／附件的修改时间，跳过已识别的编译产物、Git 和应用元数据；无法安全读取时显示“未知”。最近打开时间只放在提示中，不冒充修改时间。

点击左上 LatexStudio 返回项目首页，不丢弃、重置或偷偷保存当前草稿；点击当前项目继续原编辑。选择其他论文时仍先保存当前草稿，冲突或失败不会切换。移出列表只删除本机入口，不删除硬盘论文。PDF 上方“日志”按钮可打开／收起编译日志，日志右上角 × 也可关闭；日志仅位于源码／PDF 下方，左侧文件树和大纲保持完整高度。布局菜单仍可显隐文件栏、PDF 和日志；编译失败会展开日志。

每个项目分别保存自己的 GitHub 关联、工作文件、提交历史和待同步状态；同一账号也不共用仓库配置。先切换到目标项目，再从左侧文件栏内的“项目设置”检查当前 owner/仓库。同步按钮只操作这篇论文，不遍历其他论文。首次使用时点击“登录并设置同步”；已登录但未关联时点击“设置同步”进入当前项目设置。完成关联后，日常只需点一次“同步”，软件先保存当前草稿再交换版本，不再连续弹出同步确认框；授权、创建仓库和真实冲突仍需要明确处理。项目名相同不代表同一目录，悬停可看本机路径。

## 1. 登录自己的账号

启动弹窗提供“GitHub登录”和“离线使用”。点击登录后，软件取得本次短码并自动在系统浏览器打开 GitHub 官方授权页，不再要求第二次“继续”确认或手动找入口。将界面显示的验证码输入 GitHub，可点“复制验证码”后粘贴；核对你创建的 App（当前配置对应 `latexfactory`）和自己的账号，完成授权后软件会自动更新登录状态。浏览器未打开时可点“重新打开 GitHub”。

按本轮选择仍使用设备授权，保留短码步骤；没有伪造自动填码。验证码只在有效授权期间显示，复制由你明确点击触发，不自动改动剪贴板；取消后界面清码，但不擅自清空系统剪贴板。账号与会话的详细说明收在“账号与授权”中。

选择“离线使用”或按 Escape 可直接进入本地工作台，不发起账号授权、打开浏览器或自动上传。即使账号状态仍在读取或此版本未配置登录，也无需等待即可离线使用。此选择只作用于本次启动，后续状态刷新／项目切换不会重新弹出；想协作时可从右上角头像菜单的“账号与授权”登录；登录后显示当前 GitHub 头像和用户名，头像离线或加载失败时回退姓名／用户名首字。未登录不限制本地编辑、保存和历史；编译仍遵守原有本地组件校验与平台支持限制。

登录不创建仓库、不上传论文、不邀请任何人。0.3.8 起，访问与续期凭据仅由主进程使用，并以操作系统安全存储加密保存；短期访问到期前自动续期，退出应用不主动清掉有效授权，重启先向 GitHub 重新验证身份。断网保留加密授权，联网后自动重试，不要求反复重新授权，也不把尚未验证的身份当作仓库写权限。点击“退出账号”会清除本机登录；GitHub 撤销授权、续期授权失效或系统安全存储不可用仍是例外，后者仅本次运行有效。不会保存 App Secret、向界面发送任何令牌或关闭 GitHub 到期策略。旧版没有保存续期凭据，升级后需退出并重新登录一次，以后不必因数小时的访问期限反复登录。全局撤销通过 GitHub 官方设置完成，不会删除仓库或论文。

## 2. 为当前论文创建私有合作项目

1. 先打开或创建一个本地论文项目。
2. 从左侧当前论文文件栏打开“项目设置”，在“创建或加入合作项目”填写项目名称，例如 `my-paper`，点击“创建私有合作项目”并确认。若有草稿，软件先尝试保存；失败则不进行远端创建。
3. 创建请求固定 `private:true`，没有公开选项。返回的仓库若不是确认的私有仓库，软件停止关联和上传，不自动修改可见性。
4. 创建/关联本身**不上传论文**。准备好后点击左侧文件栏内的“同步”，这次明确点击即为保存并交换版本的操作，不需要再次确认；自动同步仍默认关闭、仅可显式开启。

若提示“仓库已创建但尚未授权 App”，不要重复创建。点击“管理 GitHub 项目授权”，由仓库所有者在官方页把**已经创建的那个私库**加入 App 安装范围；返回 App 刷新“我的云端项目”，选择它关联当前本地论文。

也可以从“我的项目与合作邀请”查看已经授权的私有项目，明确选择关联当前论文或下载到一个空目录；软件不自动拿任意已有目录覆盖下载。

## 3. 邀请另一个人

关联并明确同步需要共享的文件后，点击工作台右上角“分享”，直接显示可复制的项目链接；在同一窗口展开“邀请合作者”：

1. 输入对方的 GitHub 用户名，点击“发送合作邀请”，核对原生确认中的目标账号和项目。
2. 点击“复制链接”，将 `latexstudio://join/owner/repository` 发给对方；分享本身不上传文件。
3. 分享链接只是定位项目，不是访问密钥。未获授权的人拿到链接仍不能读取私库；软件不会为了分享而公开仓库。

当前用户必须有仓库管理权限才能邀请；App 本身获准 Administration 权限不等于每个使用者都成为管理员。邀请给对方的是编辑权限，不授予仓库管理权。

## 4. 对方加入同一个项目

对方使用自己的 GitHub 账号登录，点击分享链接打开“加入项目”，或从首页／账号菜单选择“加入项目”并粘贴链接。在该窗口查看并明确接受与目标相同的邀请；原有官方通知页入口仍可处理 GitHub 邀请。

邀请接受与 App 安装授权是不同事情：仓库所属账户的 App 安装也必须覆盖该项目。对方不必注册自己的 App，也不应为了读你的仓库而在无关账户随意安装一个副本。

获得权限后，点击“选择本地文件夹并下载”，先验证访问权限，再由原生选择器选择空目录。成功后进入这个项目，每个人的电脑保留独立的真实文件与 Git 工作副本，并同步同一个原仓库，不另建仓库、不依赖同一网络或 NAS。取消目录选择不改变当前项目；链接不触发自动下载。安装版的 OS 协议关联、便携／开发入口的粘贴方式与完整步骤见[项目分享说明](<PROJECT-SHARING.md>)。

## 5. 同步、离线和冲突

- **保存**先写本机文件，本地写作和已自动配置的编译不需要 GitHub 账号或网络；Windows 组件已内置，首次后台校验不要求手动下载。
- **同步当前论文**先保留本地 Git 快照，再重新确认当前账号、仓库、分支、私有状态和写权限，交换明确提交的版本；不强推。
- **自动同步**默认关闭，只在当前会话明确开启。每 30 秒检查一次，忙碌、有未保存草稿、关闭或会话失效时跳过；不会周期性替你保存正在输入的草稿。首次错误或分歧就停止，需用户确认后重新开启，不悄悄反复写远端。
- 这不是逐字实时协同。建议两人编辑不同章节/文件，并在开始工作前、交接前明确同步。
- 双方独立修改造成历史分歧时，软件保留本地快照和远端获取的对象，不自动合并或覆盖。**本轮尚无完整自动合并/图形冲突解决器**；停止自动同步、先备份和比较，必要时由维护者协助整理，不连续强行重试。
- 网络中断、取消或超时后，远端创建/邀请/推送可能已经生效。先在 GitHub 官方页核对，再刷新；不能把本地报错当作远端一定未发生。

## 6. 谁改了什么、怎样回退

点击工具栏“修改历史”进入参考 Overleaf 的独立只读模式：左侧记录文件、中间宽源码比较区、右侧全高时间线。选择记录查看带行号的增删高亮，可比较同文件的较早版本、跳转修改处；点击“返回编辑”保留当前草稿。初始记录不把全文标为新增，显示超限明确提示。这里包含当前论文的本地保存记录和 Git 文件变化；切换论文立即清掉旧记录及选择，随后读取新论文历史。GitHub 两端共同看到的是已经交换的 Git 提交；尚未同步的本地逐次日志不会自动上传。

选择版本可以回退**一个现存文本文件**，不是整个项目、删除文件或二进制恢复。未保存草稿须先保存或取消，界面/原生确认后仍检查当前内容版本；期间有别人或外部工具改动则拒绝覆盖。回退新增记录，不删除旧历史，随后明确同步才能分享该次回退提交。

作者是 OS 显示名或 Git 提交作者，不是逐次键盘输入的认证证据；无法确认的外部修改标记为未知。更多配额/锁/恢复限制见[项目历史说明](<PROJECT-HISTORY.md>)。
