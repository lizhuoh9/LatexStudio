# 分享项目与加入同一个仓库

## 发起者

1. 打开已关联 GitHub 私有仓库的论文，先点“同步”，把需要共享的文件提交到原仓库。分享链接本身不上传文件。
2. 点工作台右上角“分享”，即可看到并复制 `latexstudio://join/owner/repository` 项目链接，不必再在项目设置中寻找。
3. 对方尚无仓库权限时，展开“邀请合作者”，填写对方的 GitHub 用户名并确认邀请。发起者需要真实仓库管理权限；链接不会公开仓库或授予管理员权限。

## 接收者

1. 安装支持项目链接的 LatexStudio 版本，使用自己的 GitHub 账号登录。
2. 点击项目链接，由操作系统确认打开应用；如果没有自动打开，在软件首页或账号菜单中点“加入项目”，粘贴链接。也接受标准 HTTPS GitHub 仓库地址。链接不包含登录凭据。
3. 需要时点“查看此项目的邀请”，明确接受与链接目标一致的邀请。接受邀请与 GitHub App 安装范围是不同事情：仓库所有者的 LatexFactory 安装也必须覆盖这个私有仓库。
4. 点“选择本地文件夹并下载”。软件先验证项目权限，再让你选择一个**空文件夹**；不会从链接接受任意本地路径，不会覆盖现有论文。取消选择不会切换当前工作区。
5. 下载成功后自动进入本地项目。编辑和保存只写自己的工作副本；点击“同步”才向**原来的同一个 owner/仓库/默认分支**交换版本，不会复制创建另一个 GitHub 仓库。

自动同步仍默认关闭。下载期间可明确取消传输；中断或异常可能留下部分下载，请检查后选择另一个空目录重新操作，不自动删除文件或悄悄重试。草稿保存失败、冲突、权限或分支变化会阻止不安全操作。

## 链接与平台

- 安装包声明固定 `latexstudio` 协议；只在正式打包、非便携运行中请求操作系统关联。开发桌面入口、便携版或系统没有设置关联时，使用“加入项目”粘贴链接即可。不会为开发 Electron 修改系统协议关联。
- 打开链接只显示目标和操作选择，**不自动登录、接受邀请、选择目录、下载或同步**。关闭或其他对话框期间会保留最新待处理链接。
- 项目链接只是定位信息，不是私库访问密钥。没有权限的人不能凭链接下载；当前登录账号、仓库私有状态、安装范围、分支和写权限仍由主进程重新验证。
- 本轮使用隔离配置验证实际构建的界面、深链接IPC、目录取消、主进程项目提交和本地编辑保存；Cloud 权限、账号展示、邀请、选择器及克隆数据在该界面验收中为明确的本地模拟。此前真实同账号两目录同步已经验证，但这不等于本轮完成两个真实人员账号的邀请／同步或实际安装后的 OS 协议验收。
- macOS 当前仍是编辑测试版本，本地 TeX 编译、真实 Mac GUI、受信签名及安装升级验收限制不变。
